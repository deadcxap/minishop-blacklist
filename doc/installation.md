# Установка и настройка

Плагин предназначен для Minishop 3.8.5. Пакет использует Plugin API 1, `ui_composition: 3` и `durable_jobs: 1`.

## Установка из пакета

1. В админке Minishop откройте «Плагины». Загрузите `minishop-blacklist-<версия>.zip` из файлов релиза или укажите URL публичного репозитория плагина. При первой установке сверяйте открытый ключ издателя с `publisher.pub` поставки.
2. Активируйте плагин и дождитесь, пока Minishop применит пакет в веб-процессе и воркере. Воркер создаёт первый снимок настроенных источников.
3. Откройте карточку плагина и выберите «Настройки».

## Источники и отображение

- В поле «Ссылки на списки» укажите по одному публичному HTTPS-адресу на строку. Две стартовые ссылки заполнены при установке. Можно добавить до 20 источников и оставить список пустым, чтобы прекратить сопоставление.
- Интервал задаётся целым числом часов. По умолчанию это 24 часа. Новый источник будет загружен при ближайшей проверке воркера.
- Нажмите **Обновить списки** для внеплановой загрузки всех сохранённых источников. Сначала сохраните изменения ссылок, если хотите применить их к загрузке. Пока воркер обновляет списки, панель показывает ход операции и обновляет состояние источников.
- Строка списка содержит Telegram ID. После первого `#` можно указать причину и ссылки. Пример с вымышленным ID и адресом доказательства

  ```text
  1000000001 # Причина совпадения https://example.org/reference
  ```

- При совпадении показываются все различающиеся комментарии. Одинаковый текст отображается один раз со всеми его ссылками. Каждая иконка ссылки открывает адрес в новой вкладке.
- Для каждого источника в настройках видны время последней попытки при ошибке, дата успешной загрузки, число уникальных Telegram ID и состояние загрузки. При сбое используется предыдущий снимок. Источник, удалённый из настроек, сразу исключается из сопоставления.
- Переключатель «Списки пользователей» управляет отдельным разделом и, при наличии `admin_users_table` версии 1, значениями в штатной таблице пользователей. При выключении выбранный фильтр чёрного списка пропускает все аккаунты. Вкладка в карточке и блок в открытом тикете включаются отдельно.

## Уведомления

Укажите числовой ID чата, выдайте боту Minishop право отправлять сообщения и при необходимости задайте числовой ID топика. Оставьте поле топика пустым для отправки в чат. Отметьте события, по которым нужны уведомления. Флажок «Все» включает регистрацию, триал, оплату и истечение. При установке все события отключены.

Для регистрации проверяется привязанный Telegram ID. Для оплаты учитывается успешный платёж положительной суммы, в том числе пополнение баланса. При платном триале возможны отдельные уведомления об оплате и активации. «Истёк» совпадает с событием истечения подписки, которое публикует воркер Minishop.

При обновлении с `0.2.0` оставшиеся тестовые отправки отменяются. Сохранённые настройки обычных уведомлений применяются и после обновления. Существующие записи старого журнала сохраняются в базе, сбор новых записей прекращается.

## Сборка и выпуск

Сборка использует Python 3.12 и Node.js 22. Для локальной проверки с тестовым ключом выполните команды из корня репозитория в отдельном окружении Python.

```bash
python -m pip install -r requirements-build.txt
npm ci --ignore-scripts
npm run check
npm run build
npm test
python scripts/build-package.py init-key
python scripts/build-package.py build
```

Ключ создаётся один раз в `.local/publisher/minishop-blacklist.key`. Готовый пакет и индекс находятся в `dist/release`. Для повторной сборки используйте существующий ключ. Для проверки валидатором Minishop можно передать `--verify-host` в окружении, где доступны Python-модули Minishop 3.8.5.

### Публикация по тегу

GitHub Actions запускает выпуск только при отправке нового тега `vX.Y.Z` в репозиторий. Для подписи используется секрет `MINISHOP_BLACKLIST_SIGNING_KEY` с постоянным приватным ключом Ed25519 в виде 32 байт, закодированных в Base64.

1. Укажите номер выпуска в `pyproject.toml` и `backend/minishop_blacklist/__init__.py`. Для обновления `package.json` и `package-lock.json` выполните `npm version <версия> --no-git-tag-version`.
2. Добавьте раздел `## <версия>` с описанием выпуска в [CHANGELOG.md](../CHANGELOG.md) и закоммитьте изменения в `main`.
3. Отправьте коммит в `origin/main`, поставьте тег на этот коммит и отправьте тег. Для примера ниже подготовленный коммит с версией `1.0.1` должен быть текущим `HEAD`.

```bash
git push origin main
git tag -a v1.0.1 -m "Minishop Blacklist 1.0.1"
git push origin refs/tags/v1.0.1
```

Workflow проверяет совпадение версии пакета с тегом и собирает ZIP из отмеченного коммита. Подписанный архив, индекс, открытый ключ и контрольная сумма попадают в `main` одним коммитом. Эти же файлы прикладываются к GitHub Release. Тег остаётся на коммите исходников, а описание релиза берётся из соответствующего раздела журнала изменений.

При установке по адресу репозитория Minishop получает актуальный пакет из `main`. Для установки конкретного выпуска загрузите ZIP из вложений его GitHub Release. Если выпуск прервался, повторно запустите задания оригинального прогона для этого тега через **Re-run jobs**.

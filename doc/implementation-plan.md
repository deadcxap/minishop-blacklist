# Реализация чёрного списка для Minishop

Первая версия плагина — `0.1.0`. Он сопоставляет Telegram ID клиентов Minishop с настраиваемыми внешними списками, показывает совпадения в админке и уведомляет администратора о выбранных событиях. Совпадение не меняет доступ клиента, состояние подписки или обработку оплаты.

## Совместимость с Minishop 3.8.5

Целевая версия — Minishop `v3.8.5` (`2b6d2ce6`). Плагин использует Plugin API 1, `ui_composition: 3` и `durable_jobs: 1`. [Возможности будущих версий API](future-api.md) вынесены в отдельный план.

| Интерфейс | Контракт и ограничение |
| --- | --- |
| Настройки плагина | `frontend.settings_tabs` открывает собственную форму в разделе «Плагины → Настройки». Плагин сохраняет настройки в своих таблицах через админский API. |
| Карточка `/admin/users/{ID}` | `frontend.user_panels` добавляет вкладку «Чёрный список». |
| Открытый тикет `/admin/support/{ID}` | `admin.support.ticket.content` размещает блок над редактором ответа. Слот доступен с `ui_composition: 3`, передаёт выбранный тикет и Telegram ID его автора при наличии привязки. |
| «Пользователи из blacklist» | `frontend.sections` добавляет пункт меню и страницу со штатной навигацией. На 3.8.5 переключатели плагина управляют показом информации. Пункт меню и вкладка карточки имеют статические дескрипторы, поэтому отключённое представление открывается с пояснением. |

Основания проверки в Minishop — `docs/development/plugin-ui-composition.md`, `docs/development/plugins.md`, `backend/bot/plugins/package_ui_composition.py`, `frontend/src/admin/sections/runtimeExtensions.ts` и исходники штатных экранов «Пользователи» и «Поддержка».

## Общий список пользователей Minishop 3.8.6

В разрабатываемой версии при наличии `admin_users_table: 1` плагин
регистрирует столбец и фильтр «Чёрный список» в `/admin/users`. На 3.8.5
доступны представления из предыдущего раздела.

- Столбец загружает статусы всей страницы одним запросом. ❌ включает совпадения
  из последних успешных снимков. ✓ означает отсутствие совпадений после проверки
  всех источников. ? отмечает неполную проверку, а «—» обозначает аккаунт без Telegram.
- Фильтр применяет те же условия к запросу Minishop вместе с поиском и
  штатными фильтрами до подсчёта и пагинации.
- Миграция `0005_users_table_visibility` включает показ при установке и
  обновлении. Переключатель в настройках скрывает столбец и фильтр. При
  выключенном показе список игнорирует соответствующее условие из сохранённой ссылки.
  После сохранения смены переключателя админка перезагружает страницу настроек
  и сбрасывает кеш списка.

## 1. Каркас и настройки

- Выделить Python-пакет с точкой входа `minishop.plugins`, каталог административного TypeScript-интерфейса с отдельным ESM-бандлом, каталоги локализации и скрипты сборки. Использовать `setup_web`, `migrations`, `worker_tasks` и штатную очередь Minishop (`durable_jobs: 1`). Изолировать стили плагина, использовать цвета и размеры темы админки.
- Добавить многострочное поле «Ссылки на списки» с одной ссылкой на строку. Включить обе стартовые ссылки в начальную конфигурацию. Период обновления задаётся в часах, по умолчанию каждые 24 часа. Показать дату последнего успешного обновления и ошибки по каждому источнику.
- Добавить отдельные переключатели для вкладки карточки пользователя, блока открытого тикета и раздела «Пользователи из blacklist».
- Добавить поля ID чата и необязательного ID топика, а также флажки событий «Зарегистрировался», «Взял триал», «Оплатил», «Истёк» и «Все». «Все» включает четыре флажка. Включение отправки требует сохранённого ID чата и хотя бы одного события.
- Проверять админскую сессию и права в каждом обработчике. Для сохранения использовать механизм CSRF Minishop. Хранить конфигурацию на сервере, чтобы веб-процесс и воркер видели одинаковые настройки.

## 2. Загрузка и сопоставление

- Загружать каждый источник воркером при первом включении и по настраиваемому интервалу. Новый адрес становится доступным для обновления сразу после сохранения. Принимать публичные HTTPS-адреса, проверять адрес назначения перед соединением и после редиректов, ограничивать размер ответа и время скачивания.
- Разбирать UTF-8. Первый `#` отделяет числовой Telegram ID от причины. Из причины извлекать безопасные ссылки и сохранять остальной текст. Пропускать пустые строки и комментарии, учитывать число некорректных строк. Оба стартовых файла проверены. Встречаются повторные ID в одном файле, пересечения между файлами и несколько ссылок в одной записи.
- Хранить совпадения по Telegram ID и источнику. Показывать все различающиеся комментарии внутри одного списка и между списками. Одинаковый текст выводить один раз со всеми различающимися ссылками этого текста. Использовать отдельные таблицы плагина. Успешное обновление заменяет снимок одного источника целиком. При ошибке сохраняется его последний успешный снимок с отметкой об устаревании. Удалённый в настройках источник сразу исключается из сопоставления.
- Сопоставлять по `telegram_id` привязанного аккаунта. Показывать «Совпадений нет» после проверки всех настроенных источников. Для аккаунта без Telegram или при неполной проверке показывать соответствующий статус. Положительное совпадение отображать и при сбое другого источника. Результат из устаревшего снимка помечать, а дату загрузки показывать в настройках. В выдачу отдельной страницы включать только существующих пользователей Minishop.

## 3. Интерфейс на штатной версии

- Добавить раздел «Пользователи из blacklist» с постраничным списком совпавших клиентов и переходом в штатную карточку пользователя.
- Добавить вкладку «Чёрный список» в карточке клиента и блок статуса в открытом тикете. Для совпадения показать причины текстом и по доступной иконке на каждую ссылку. Ссылка открывается в новой вкладке. Для записи только со ссылкой достаточно статуса и иконки.
- Выдавать состояние и совпадения через пакетный запрос к админскому API. Выводить причины как обычный текст и делать иконки различимыми для клавиатуры и экранного диктора.

## 4. Уведомления в Telegram

Подписать плагин на события Minishop. Для регистрации проверить Telegram ID из события по сохранённому аккаунту. Для остальных событий получить его по внутреннему `user_id`.

| Настройка | Событие | Правило первой версии |
| --- | --- | --- |
| Зарегистрировался | `user.registered` | Регистрация с привязанным Telegram. Создание аккаунта через синхронизацию панели пропускается по примеру штатного уведомления. Последующая привязка Telegram имеет отдельное событие. |
| Взял триал | `trial.activated` | Успешная активация триала. |
| Оплатил | `payment.succeeded` | Успешный платёж положительной суммы. Включает пополнение, покупки с баланса, покупку подарка, автопродление и платный триал. Платный триал может вызвать два разных уведомления при включённых категориях. |
| Истёк | `subscription.expired` | Истечение подписки по сигналу воркера Minishop. Воркер проверяет окно первых 24 часов и пропускает подписки, исключённые правилами Minishop, в том числе заменённые новой активной подпиской. |

- Повторить структуру штатного уведомления «👤 **Новый пользователь**» в HTML Telegram. Для совпадения показать заголовок, событие, имя и Telegram ID, время, причины и кнопку перехода в карточку. Экранировать подставляемый текст, учитывать лимит сообщения и использовать настроенный чат и топик. Боту нужны права отправки в этот чат.
- Для оплаты использовать `DurableSubscription`. Minishop сохраняет задание с `payment_db_id` в транзакции платежа. Пополнение баланса в 3.8.5 поступает через обычное событие `payment.succeeded` после коммита. Для пополнения, регистрации, триала и истечения ставить задания из обработчиков шины событий. Воркер проверяет, что действие зафиксировано, актуальные настройки разрешают отправку и есть совпадение, затем обращается к Telegram. При неполной проверке и отсутствии совпадения воркер ограниченное число раз откладывает решение до загрузки источников. Ключ операции защищает от повторной постановки задания. Для истечения ключ включает идентификатор подписки и дату окончания, чтобы очередное истечение после продления считалось отдельно.
- Для событий шины остановка процесса до записи задания может привести к пропуску уведомления. При первом запуске задания до коммита воркеру может потребоваться повторная проверка. Сетевой тайм-аут после принятия сообщения Telegram может привести к дублю при повторной попытке. Плагин обрабатывает новые события по мере их поступления.

Основания проверки в Minishop — `docs/architecture/events.md`, `docs/development/plugin-extensions.md`, `backend/bot/services/notification_service.py` и `backend/bot/services/subscription_notification_worker.py`.

## 5. Приёмка и выпуск

1. Проверить разбор с пустыми строками, дублями, несколькими ссылками, ошибкой скачивания и обновлением источника с удалёнными ID. Проверить интервал по умолчанию и смену интервала, сохранение предыдущей успешной загрузки при сбое и исключение удалённого источника.
2. Проверить установку подписанного пакета на стабильном Minishop 3.8.5. Проверить права доступа к настройкам и данным, карточку, открытый тикет, раздел меню, светлую и тёмную темы и мобильный размер экрана.
3. Прогнать реальные сценарии регистрации, активации триала, оплаты и истечения на стенде с тестовым ботом. Проверить чат и топик, флажок «Все», отключение отдельных событий, совпадение из двух источников, повтор события и временный отказ Telegram.
4. Подготовить коммит исходников в `main` и записать изменения версии в корневой [CHANGELOG.md](../CHANGELOG.md). Публикация запускается при отправке тега `vX.Y.Z` на подготовленный коммит. Отправка изменений и тегов требует подтверждения владельца. [Инструкция выпуска](installation.md#публикация-по-тегу)
5. Собрать подписанный Ed25519 ZIP с `plugin.json`, Python-пакетом, локализациями и собранным интерфейсом. GitHub Actions прикладывает архив и файлы поставки к GitHub Release и обновляет `main` одним коммитом. Индекс указывает на архив в том же коммите. Поэтому Minishop может установить актуальный пакет по адресу репозитория, а ZIP конкретной версии можно скачать из GitHub Release.
